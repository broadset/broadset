# Cross-Region CT Inventory — 2026-04-28

Closes RQ-3.1 + RQ-3.2 from `release-quality-closure-plan.md`. Maps every cross-region acceptance criterion in `project/spec/{editor,ui,demo}/` to existing Playwright CT coverage in `packages/demo/ct/` and `packages/ui/ct/` and surfaces the gap list with concrete CRA-2.x follow-up unit stubs.

## Scope and method

**Region taxonomy.** The CT derivation rule (`agents/instructions/testing.instructions.md`) defines eight UI regions: `canvas`, `transform widget`, `properties panel`, `layers panel`, `toolbar`, `timeline`, `modal`, `bottom bar`. For this inventory the toolbar region is sub-divided where useful (`main toolbar`, `element toolbar`, `sidebar toolbar`, `animation toolbar`, `scene sorter`, `placement banner`, `context menu`) so a `THEN` row can pinpoint the exact surface that must visibly update.

**Method.** Every spec file under `project/spec/editor/`, `project/spec/ui/`, and `project/spec/demo/` was read in full. For every `### Requirement:` heading the `#### Acceptance Criteria` bullets were enumerated and each bullet was classified:

- **cross-region** — `WHEN` action targets one region and `THEN` asserts a visible change in at least one _other_ region. Source region and every affected region are recorded.
- **single-region** — `WHEN` and `THEN` resolve to the same region.
- **non-UI** — pure data, store, math, schema, or persistence behavior with no UI surface (e.g. parsers, dirty flag plumbing, snapshot determinism).

Cross-region rows were then matched against the CT inventory in `packages/demo/ct/` and `packages/ui/ct/` (28 CT files across `accessibility/`, `canvas-transform/`, `editing/`, `layout/`, `state/`, `timeline/`, plus the two UI-package CTs). A row is `covered` when at least one existing test exercises every affected region for the same source action; `partial` when one region (typically the canvas-side commit) is covered but the corresponding off-canvas region is not asserted in the same test; `missing` when no existing test exercises the flow.

**How to update.** When a new acceptance criterion is added, append a row to its spec section below with classification, regions, and verdict. When a CT lands, flip the matching `partial`/`missing` row to `covered`, retire the corresponding CRA-2.x stub, and shrink the gap list. The Gap List ordering is `THEN` region first (canvas → transform widget → properties → layers → toolbar/menus → timeline → modal → bottom bar) so the next agent can attack canvas-visible regressions first.

**Tally.** 14 spec files reviewed. 261 acceptance criteria classified — **120 cross-region**, **61 single-region**, **80 non-UI** (single-region totals include rows whose `WHEN` and `THEN` collapse to one region; non-UI counts include both pure logic and configuration rows whose `THEN` is non-UI). Cross-region acceptance bullets break down as **70 covered**, **17 partial**, **33 missing** (initial baseline was 65/22/33; +5 covered after CRA-2.18, CRA-2.19, CRA-2.25, CRA-2.30, and CRA-2.36 landed). The Gap List below consolidates the 50 partial + missing acceptance bullets into **69 open work-queue rows** that group bullets sharing a single source flow / target CT (the row total exceeds the bullet total because some flows surface across two specs — e.g. context-menu rows appear in both `ui/toolbar-nav.md` and `demo/layout.md`). The matching CRA-2.x stubs below pair 1:1 with the open gap rows; retired stubs link to their landed CT.
